# Spark-I 六模块与正式启动

机器人主工程位于 `/home/spark/SUAT/spark`，使用 ROS 1 Noetic。六个模块沿用四个源码子包，ROS 入口由同一个 `suat_mission` catkin 包提供。

在机器人终端加载环境后，可按模块独立开发。现场条件满足后再使用表中的动作入口。

```bash
cd /home/spark/SUAT/spark
source /home/spark/spark_noetic/devel/setup.bash
source devel/setup.bash
```

| 模块 | 源码与现场资源 | 单模块入口 |
| --- | --- | --- |
| 1 场地、地图和坐标 | `navigation/`、`data/maps/`、`data/waypoints/` | 用 `python3 tools/selected_map.py --path` 查看当前图。新布局用 `roslaunch suat_mission mapping_field.launch` 建图。静态图定位用 `python3 tools/start_field_localization.py --start --at-start-a`，适用于已摆在保存的 A 起点且驱动尚未启动的情况。 |
| 2 导航和底盘对准 | `navigation/`、`config/navigation_test.yaml`、`data/navigation/` | 用 `python3 tools/start_field_navigation.py --describe --owner mission --speed slow --planner rollout` 核对参数。去掉描述选项、按需改为 `--start --owner field` 可启用独立导航；用 `rosrun suat_mission field_navigation.py --help` 查看定点与路线入口。 |
| 3 分类板与 AR | `vision/board_recognition.py`、`data/calibration/board_view_candidates/` | 读板站停稳且相机出图后运行 `python3 tools/read_board_camera.py --geometry data/calibration/board_view_candidates/classification_arrival_20261115_03_v1.json --output reports/runs/board_preview_$(date +%s)`。本局 B/C/D 映射由板面得出。 |
| 4 物块识别和抓取坐标 | `vision/`、`manipulation/pickup_geometry.py`、`data/calibration/` | `roslaunch suat_mission field_perception.launch` 启动独立感知。已启动 RGB-D 时可用 `rosrun suat_mission arm_pick_place.py --observe same --target cake` 取景并对照 DLT、厂家四系数。 |
| 5 机械臂反馈、抓放与运输 | `manipulation/arm_session.py`、`automation/serial_mission.py` | `python3 tools/arm_workpose.py --target 200 0 150` 查看空载工作位。独立抓放命令的执行选项见 `rosrun suat_mission arm_pick_place.py --help`。正式流程使用串口实测到位、单段垂直抬升及持物、释放证据。 |
| 6 任务编排和计时 | `automation/`、`config/mission.yaml`、`launch/mission.launch` | 现场优先使用下面的一次 Enter 入口。可用 `python3 tools/check_readiness.py --help` 查看资源检查入口。 |

## 一次 Enter 启动

比赛摆位为 A 红色收取区、车头朝 D。分类板就位，蛋糕叠在中央。启动器负责相机、RViz、A 点定位、读板、取物、运送和释放。提示出现后按一次空行 Enter。

```bash
cd /home/spark/SUAT/spark
bash tools/run_match.sh cake-only --at-start-a --speed slow --planner rollout
```

默认任务配置从西、南、东、北的四侧接近站选择目标。分支二已接入本局读板、换侧重试、持物后运输、释放确认和剩余时间检查。全局规划器按当前配置使用 `global_planner/GlobalPlanner`，局部模式可选 `rollout` 或 `dwa`。

整场模式使用已部署的独立 39 cm 候选。它加入多吸附点选择和低速补位，保留中央绕行。四侧可达、载物净空和 B/C/D 实物释放仍待验收。

```bash
bash tools/run_match.sh full --at-start-a --speed slow --planner rollout --mission-config src/suat_mission/config/mission_full_pickup_39_candidate_20261119.yaml
```

运行后先查 `reports/runs/<run_id>/result.json` 中的 `report.phase`、`report.error` 和 `delivered_confirmed`。同一蛋糕 ID 的抓取、运输、落入 A 红区及一次计数均需对应真实证据。启动目录的 `resource_selection.json` 和 `start_localization.json` 记录本次配置与定位。
